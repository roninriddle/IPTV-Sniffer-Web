推荐操作路径

            
先发现频道，再建立稳定订阅。

            
系统从机顶盒开机流量中提取频道、组播参数和认证信息。完成发现后，在订阅中心选择频道，播放器始终使用固定订阅地址。

          

          

            第 1 步
            发现运营商频道
            导入频道库，并自动提取可用认证信息
            
          

        


        

          

            
              唯一推荐拓扑：交换机镜像口
              只捕获机顶盒开机流量
            
            

              

                
交换机镜像口

                
光猫 IPTV 口 → 交换机
  ├─ 机顶盒端口（被镜像源）
  └─ 宿主机端口（镜像目标）

                
✓ 抓机顶盒开机流量、频道表、FCC/FEC、Option60
✓ 生成订阅清单和 rtp2httpd 源文件
✓ FNOS 容器需在「高级设置 → 功能」勾选 NET_RAW；实验性认证还需 NET_ADMIN
✗ 镜像口不能主动发 IGMP/FCC，因此不能代表 rtp2httpd 可直接播放

              

            

          

        


        

          

            1. 运营商频道发现（主入口）
            填写机顶盒 IP，点击「开始捕获」后重启机顶盒，系统自动从 STB 开机流量中解析频道表与 DHCP 认证信息（MAC / IPTV IP / Option60 等），一键导入到频道库。
          

          

            2. IPTV 认证（需要主动播放时）
            FCC 服务器、回看服务器与组播流均在 IPTV 子网，未认证时 rtp2httpd 不可达。完成 IPTV 认证后，FCC 快速换台和回看才能正常工作。
          

          

            3. 订阅中心
            从频道库选定要看的频道，加入订阅。播放器使用固定的动态订阅地址；频道源、FCC 或回看地址刷新后，无需重新导入订阅。
          

          

            4. 播放诊断
            先检测 rtp2httpd、M3U、FCC、IGMP 和组播回流，判断问题在播放列表、配置、上游链路还是镜像口限制。
          

          

            5. EPG 与台标维护
            在「订阅中心 → 高级设置」中管理 XMLTV EPG 与台标来源，可手动刷新并重新匹配 tvg-id / tvg-logo。

播放链路诊断

              按 rtp2httpd、认证、FCC、组播、M3U 分层定位播放失败点
            

            
点击「运行诊断」检查 rtp2httpd 是否可访问、FCC 是否响应、认证信息与频道列表是否就绪，给出排查结论。填写「检测频道」后，还会主动发起 IGMP 加入并检测是否收到 239.x UDP 组播流，分开显示线上数据、实际 IGMP、应用接收和媒体证据；镜像口仅作为排查线索。组播链路检测需要宿主机 tcpdump 及 NET_ADMIN、NET_RAW 权限。

            

              镜像口说明：
              交换机镜像口只适合捕获机顶盒流量，不能代表本机能主动播放。若诊断显示“未加入也能看到流量、主动加入收不到”，请到「IPTV 认证」页按选定网口生成脚本或执行实验性认证，再让 rtp2httpd 使用完成认证的上游网口。
