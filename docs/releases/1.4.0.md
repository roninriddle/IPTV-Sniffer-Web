# IPTV Sniffer Web v1.4.0

改善手机认证、订阅和静态导出体验，补充 FCC 切台请求识别，并修正北京联通 UIOS 认证状态显示。保留原有订阅地址与频道数据格式。

## 没有 FCC 也可以先使用普通组播播放

**“FCC 0 条”仅表示当前抓包或频道资料没有可用 FCC 地址，不等于运营商不支持，也不应阻止频道导入与订阅导出。**

- FCC 用于加快起播和换台。没有完整 FCC 地址与端口时，应用不追加 `fcc`／`fcc-type`，rtp2httpd 通过 IGMP 接收普通组播；起播或切台可能较慢。实际播放仍需要正确的 IPTV 认证、VLAN、上游接口、路由与组播回流。
- 频道表可能不包含 FCC；只抓开机、只留 TCP、镜像缺少方向，或抓包没有覆盖实际切台请求，都可能无法取得地址。新增解析能力不能补出原始包中不存在的参数。
- 需要 FCC 时，在完整双向镜像下连续切换多个直播频道，每台停留数秒，保留目标机顶盒的 TCP 与 UDP；停止后重新分析并导入。若接收设备已克隆机顶盒身份，应先恢复身份再接回机顶盒，避免冲突。
- 新增华为／电信格式 UDP/RTCP FCC 请求识别，按请求目标和组播频道匹配并保留来源记录；不猜测服务器、端口，也不把普通 UDP 流量当作 FCC。无法确认或频道端口有歧义时保持为空。原有频道表／URL 中的 FCC 识别继续保留。
- 没有 FCC 时若直播超时或播放几秒后断流，先查 IPTV 上游、IGMP 与组播回流，不要盲填 FCC。选择协议类型本身不能生成服务器地址。

本地北京联通 UIOS 抓包仍未发现可确认的 FCC 请求，**该线路 FCC 仍需补抓和实机验证**；本版不宣称已解决所有北京联通 FCC 场景。FCC 与回看认证相互独立，缺少 FCC 不代表缺少回看 Token。

## 手机界面与订阅

- 修复认证表单、回看参数与长文本在窄屏上的横向溢出，手机输入框和按钮尺寸更易操作。
- 订阅中心默认只显示“播放器订阅”和“rtp2httpd 原始源订阅”；EPG、HLS、全部线路与旧兼容地址折叠到“更多链接”。原有六个地址保持可用，无需更换已有播放器订阅。
- 链接完整换行显示并可直接复制；手机分区菜单自动换行。
- 静态导出“最佳来源／全部来源”使用相同的播放器 M3U 和 rtp2httpd 源 M3U 按钮。HLS 使用最佳来源，JSON／TXT／CSV 的全部来源资料单独说明。

## 北京联通 UIOS 认证显示

- 显示实际已保存会话、认证服务器、用户／机顶盒标识是否捕获，以及与当前播放 Token 匹配的运营商到期标记；不在状态接口返回会话凭据。到期标记不保证会话始终有效。
- 当前 UIOS 回看／时移流程无需填写 DES/DES3 密钥。隐藏其他平台的加密参数，避免把不适用字段为空误解为漏抓；其他 HWCU/HWCTC 流程保留。
- 认证页和诊断正确识别已保存的 UIOS 会话；自动检查成功时显示会话检查结果，避免“更新 0 个频道”造成误解。
- 定时功能验证已捕获的会话，播放时动态获取签名地址；**尚不支持会话失效后的自动重新登录**。失效后需重新解析包含有效登录及回看／时移请求的抓包。

## 升级

保留完整 `data/` 与 `output/` 目录，更新到 `1.4.0` 镜像，再刷新网页。UIOS 会话存于本地独立文件，不包含在普通设置备份中；升级或迁移前应保存整个数据目录。原有订阅地址保持不变。

镜像：`roninriddle/iptv-sniffer-web:1.4.0`、`ghcr.io/roninriddle/iptv-sniffer-web:1.4.0`；正式发布通过检查后同步更新 `latest`，支持 `linux/amd64` 与 `linux/arm64`。

## 验证范围

- 本地 321 项 Python 回归与 2 项 JavaScript 测试通过，版本一致性、语法和差异检查通过。
- 浏览器检查 320、390、1280 像素宽度，认证、订阅、回看设置及静态导出均无横向溢出。
- 北京联通实机回看和时移返回 HTTP 200，均成功解码画面；现有每 12 小时会话检查设置保持有效。FCC 识别经过合成请求测试，该北京联通线路 FCC 尚未现场验证。
- 正式镜像由同一提交完成 Linux/macOS 回归、amd64/arm64 构建与运行检查、SBOM 和可修复 HIGH/CRITICAL 漏洞检查后发布。
