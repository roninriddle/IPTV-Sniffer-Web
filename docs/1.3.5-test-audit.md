# 1.3.5-test 审计与版本归因

基线为 `v1.3.3`（`0c9324d12cb865f6aa60d903e425e3317b9e402b`）。本次为测试版，正式稳定版本仍为 1.3.3。

## 可能由 1.3.3 引起的现象

| 旧版问题 | 已验证行为 | 对历史故障的判断 | 1.3.5-test 状态 |
|---|---|---|---|
| pcapng 未明确报错 | 同一合成 gzip CUSetConfig 响应，经典 PCAP 得到 1 频道，pcapng 得到 0；旧版在文件头判断处返回空流集合 | 若实际输入是 pcapng 且走该分析入口，可以解释零频道；未取得原始现场文件，不能确定当时根因 | 明确报错要求转换；仍不原生支持 pcapng |
| B09：DHCP 身份关联错误 | 多客户端合成抓包可能选中其他终端 MAC/租约 | 可能造成认证参数错误，不证明历史现场触发 | 关联事务 ID、MAC 和目标 STB IP，歧义时不猜测 |
| B11：组播接收漏计 | 把 recvfrom 发送端 IP 当组播目的地址比较，收到包仍可能记为零 | 可能导致诊断假阴性，不等于实际线路无流量 | 按目标组成员 socket 收包统计 |
| B10：自动刷新推迟 | 重启后首次刷新期限随循环不断后移 | 可能造成回看令牌到期后未更新，不代表认证算法无法软件计算 | 持久化调度期限，失败退避 |
| B08：初始恢复点覆盖 | 状态读取覆盖原始配置快照 | 使用过认证/恢复时可能无法还原原配置；没有现场因果证明 | 初始快照保护，后续读取不覆盖 |

不能由这些 BUG 推出“旧版不能解析所有 gzip/HWCU”。合成 gzip CUSetConfig 响应在 1.3.3 经典 PCAP 中可以解析。旧版也已有客户端生成 Authenticator 的实现；具体平台适配仍取决于算法、合法凭据和门户流程。

SSH 的 `-T/-tt`、shell 续行、tshark 字段名、grep 行计数、IP/MAC 归属、帧号叙述及文档脱敏错误属于操作文档问题，不会通过升级本项目自动纠正。

## 本次修复与优化

- 保留 1.3.4-test 的备份往返、同名多线路导出、订阅地址、HLS 校验、设置校验、认证恢复点、DHCP、刷新与组播诊断修复。
- 增加持久调度、协议适配器与来源证据、备份暂存及失败回滚、媒体配额和取消、分层诊断、顺序自动保存。
- 限制下载、解压、PCAP 和 TCP 重组资源，轮转并脱敏日志；锁定依赖和基础镜像，发布前执行多架构构建与扫描。
- B01 管理认证与订阅授权分离按项目所有者要求保留现状，管理端口仍需部署环境提供访问边界。

## 兼容性与未完成验证

- 经典 PCAP 上限 128 MiB，pcapng 需先转换；`tshark -F pcap` 可明确输出格式。文件扩展名不能证明实际格式。
- JSON schema v2 保留同名多线路，新版可导入旧格式；跨旧版本迁移使用 M3U。
- 恢复支持同步写入失败回滚，不保证跨文件断电原子性。
- 私网 IPTV 目标仍可访问，未实施完整目的地址 ACL；历史日志与 PCAP 不自动改写。
- 真实运营商长时播放、FCC、RTSP、首帧与复杂 TCP 重连仍需实流验证。合成测试不证明所有地区兼容。
